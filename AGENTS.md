# AGENTS.md

## Project

A [tree-sitter](https://tree-sitter.github.io) grammar for
[hledger](https://hledger.org) journal files, named `hledger_journal`. The
grammar lives in `grammar.js`. Everything in `src/` except `src/scanner.c` is
generated by `tree-sitter generate`, and it is committed. The bindings under
`bindings/` and the package files at the root were generated by
`tree-sitter init`.

## Dev environment

Run `nix develop`, or let direnv load it (`.envrc`). The shell provides
tree-sitter, node, hledger, gcc and emscripten. It also sets `HLEDGER_SRC` to
a pinned checkout of hledger's source, whose test suite the acceptance
harness reads.

## Commands

| Command | What it does |
|---|---|
| `tree-sitter generate` | Regenerate `src/` from `grammar.js`. Run it after every grammar change. |
| `tree-sitter test` | Run the corpus tests in `test/corpus/`. |
| `tree-sitter test -i '<name>'` | Run only the corpus tests whose name matches. |
| `tree-sitter parse -p . FILE` | Print the syntax tree for a file. Errors show up as `ERROR` / `MISSING` nodes, except MISSING hidden tokens (a zero-width `quantity` is the usual sign); use `check-files.mjs` to be sure. |
| `node scripts/acceptance/check-files.mjs test/fixtures/*.journal` | Check that the whole-file fixtures parse with no errors. Unlike `tree-sitter parse`, it also catches MISSING hidden tokens. |
| `node --test 'scripts/acceptance/*.test.mjs'` | Unit tests for the acceptance harness. |
| `node scripts/acceptance/run.mjs` | Acceptance harness: share of hledger-valid inputs from hledger's test suite that parse cleanly, and share of hledger-invalid inputs that don't. Writes `.cache/acceptance/report.json`. |
| `nix flake check -L` | Everything CI runs: corpus tests, fixtures and the acceptance thresholds. |
| `hledger -f FILE print --ignore-assertions` | The oracle: does hledger itself accept FILE? |

## Workflow for a grammar change

1. Write a corpus test in the matching `test/corpus/*.txt` file.
2. Run it with `tree-sitter test -i '<name>'` and watch it fail.
3. Change `grammar.js`.
4. Run `tree-sitter generate`.
5. Run `tree-sitter test`. Everything must pass.
6. Run `node scripts/acceptance/run.mjs`.
7. Raise `minAccept` in `scripts/acceptance/thresholds.json` to the new
   acceptance rate, rounded down to 0.01. Never lower `minAccept` or
   `minReject`.
8. Commit `grammar.js`, the regenerated `src/` files, the test and
   `thresholds.json` together.

## Grammar invariants

- `extras` stays `[]`. Every space is explicit, because hledger's syntax
  depends on how many spaces there are.
- A single space never ends an account name. Two or more spaces, or a tab,
  do. `    expenses:food $10` is an account with no amount, as hledger
  reads it.
- Line ends go through `_eol`, which accepts trailing whitespace, CRLF and end
  of file. Never match a bare `'\n'`.
- Keep the typed nodes: one node type per directive and per subdirective, and
  `amount` split into `commodity` / `quantity` / `negative_quantity`.
- Use hidden rules (`_name`) for plumbing that tools don't need to see.
- When you're unsure whether some input is valid, ask hledger
  (`hledger -f FILE print --ignore-assertions`). Accepting input hledger
  rejects is a bug too, though a smaller one.

## Tests

- Corpus files in `test/corpus/` are organised by feature.
- Files in `test/fixtures/` must parse with no errors. Use them for
  whole-file properties that corpus tests can't express, such as line endings
  or a missing final newline.
- Write every test fresh. Never copy hledger's test files or another
  grammar's tests or code into this repository: hledger is GPL-3.0 and this
  repository is MIT. The acceptance harness reads hledger's tests at check
  time and does not commit them.

## Don'ts

- Don't hand-edit `src/parser.c`, `src/grammar.json` or `src/node-types.json`.
- Don't commit `.cache/`.
- Don't lower the thresholds in `scripts/acceptance/thresholds.json`.
